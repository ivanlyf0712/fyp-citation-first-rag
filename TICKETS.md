# Tickets — agentic answer layer

Status: `[ ]` todo · `[~]` in progress · `[x]` done

All tickets implemented, tested offline, and then run live against DeepSeek:
31 questions, 31 correct, 0 rejected, 31/31 citing the required unit. That score
is a ceiling (the questions are templated from row labels) — see AGENT_RESULTS.md.

## A1 — LLM client  `[x]`
`finrag/llm.py`: `DeepSeekClient` (OpenAI-compatible chat completions, `requests`,
timeout, one retry), `StubClient` (scripted replies for tests), both implementing
`complete(messages) -> (text, usage)`; token counts recorded.

## A2 — Tools over units  `[x]`
`finrag/agent_rag.py`: `search_bm25`, `search_semantic`, `read_unit`. Each returns
plain dicts, never raises on an unknown id, and is unit-tested without a model.

## A3 — Tool loop  `[x]`
Parse one JSON object per turn, execute, feed results back, stop on `answer` or
after 6 calls. Malformed JSON gets one repair prompt, then a refusal. Trace of
every step kept.

## A4 — Enforcement  `[x]`
`verify_answer()`: citations exist, numbers ⊆ cited quotes, at least one number.
Rejection returns a refusal plus the failed check; both are logged.

## A5 — CLI + logging  `[x]`
`scripts/ask.py "question"`: prints the answer, its citations and the verification;
appends one JSONL record to `annotations/runs/`.

## A6 — Scoring  `[x]`
`scripts/score_agent.py`: run every annotated question through the agent, extract
the number, compare with gold, tally correct / wrong / rejected / no-answer, and
write `AGENT_RESULTS.md`.

## A7 — Tests  `[x]`
Stub-driven: a good run; a fabricated answer (rejected); a citation to an
unrelated unit (rejected); malformed JSON (repaired once); too many tool calls
(cut off). No network.

## A8 — Docs  `[x]`
README section, `AGENT_SPEC.md` cross-linked, results file generated by A6.
